## ハイライト

> iPhone Duo は tab bar、toolbar、ナビゲーションコントロール、ステータスバーを側面へ移し、縦方向のコンテンツ領域を確保します。デザインは outer の compact width と inner の regular width の 2 種類の size class だけを狙えばよく、半折りではシステムコンポーネントが自動で折り目を避け、開閉のあいだでも機能階層は一貫していなければなりません。

## 主要内容

### 閉じればスマホ、開けばキャンバス

（[00:28](https://developer.apple.com/videos/play/tech-talks/111466/?time=28)）閉じた状態でも、iPhone Duo は片手で握れるコンパクトな形です。開けると、内側はこれまでの iPhone で最大かつ最も没入感のある画面になります。デバイスは本のように半折りにしたり、ノート PC のように机に立てたり、端で立たせたりもできます。ユーザーは場面に応じてポーズを切り替えますが、App は常に同じプロダクトとして感じられる必要があります。

### 側面コントロール：縦方向のスペースをコンテンツへ返す

（[01:09](https://developer.apple.com/videos/play/tech-talks/111466/?time=69)）閉じたあとの外画面は、従来の iPhone より広く、背が低くなります。以前は上下にあったボタンやコントロールは画面右側へ移ります。縦方向のスペースを確保しつつ、右手の親指で届きやすくするためです。左側はコンテンツ用で、面積は従来比率の iPhone の利用可能領域に近いです。

この側面スペースには、tab bar、app toolbar、戻るボタンなどのナビゲーションコントロール、再設計されたステータスバー、Live Activities に合わせて縦に展開する Dynamic Island が同居します。内画面も同じ規則でコントロールを側面に置きます。

水平バーを残す唯一のポーズは内画面の縦向きです。そこでは縦方向のスペースが足りるので、無理に側面へ押し込む必要はありません。

### 半折り：折り目がレイアウトの境界になる

（[02:03](https://developer.apple.com/videos/play/tech-talks/111466/?time=123)）本のように半折りにすると、画面中央は自然に曲がります。システムは文字や画像を中央の湾曲部から遠ざけ、ボタンやインタラクティブ要素を両側へ移します。折り目がレイアウトの自然な分割線になるのです。縦向きの半折りでは、インタラクティブ要素は下半分へ移ります。届きやすく、机の上でもデバイスが安定します。

### 分割表示とピクチャ・イン・ピクチャもポーズに追従する

（[02:42](https://developer.apple.com/videos/play/tech-talks/111466/?time=162)）iPhone Duo は慣れ親しんだ Home ジェスチャで 2 つの App を並べて表示できます。App を片側へドラッグすると 50/50 の分割表示になります。コントロールは外縁に寄り、App が左半分にあるときはコントロールも左縁へ移り、親指の届く範囲に保たれつつ中央領域を避けます。

ピクチャ・イン・ピクチャの動画は画面上部にピン留めして再生を続けられ、現在の App は残りの高さの中で縦方向にスケールします。半折りでは動画が半画面を埋め、App は動画の高さに合わせてリアルタイムに縦方向へ調整されます。

## 詳細

### Size Class は 2 種類だけ設計する。ポーズごとに別稿を出さない

（[03:50](https://developer.apple.com/videos/play/tech-talks/111466/?time=230)）ポーズは多くても、それぞれの pose 向けにカスタムレイアウトを描く必要はありません。次の 2 種類の size class に集中します。

- **Outer display**：compact width
- **Inner display**：regular width

固定幅、ブレークポイント、特定の物理画面に結びついたサイズは避けます。layout margins と horizontal safe area insets でレイアウトを組み立てます。すでにこの 2 つで組んでいる App は、多くの場合そのまま適応できます。同等の原則として、App を自由にリサイズ可能（freely resizable）にデザインすることです。

### 任意のハンズフリーレイアウト：機能を特定のポーズに縛らない

（[04:40](https://developer.apple.com/videos/play/tech-talks/111466/?time=280)）デバイスを机に立てたときは、ハンズフリー体験に向いています。メディアを上に、タップ可能なコントロールを下の安定した台座に置きます。こうした特別なレイアウトを作る場合でも、他のポーズと同じコントロール集合と全体の情報階層を維持しなければなりません。ある機能を特定の pose だけにぶら下げないでください。ユーザーはデバイスを頻繁に開閉するので、UI は予測可能で、内外で一貫している必要があります。

### 側面コントロールのマッピング規則と例外

（[05:20](https://developer.apple.com/videos/play/tech-talks/111466/?time=320)）側面の縦バーはあなたの App だけのものではなく、Live Activities やステータスバーなどシステム動的要素とも共有されます。スペースが足りないとき、App のコントロールは自動的にオーバーフローメニュー（overflow menu）へ収まります。

既存の iPhone App のマッピングはおおむね自動です。

- 上部 toolbar ボタン → 側面縦バーの上部
- 下部 toolbar ボタン → 側面縦バーの下部
- Tab bar → 引き続き下揃え

例外：右側の縦バーに収まらないほど広い toolbar 項目（テキストボタンやセグメントコントロールなど）はナビゲーションバーに残し、無理に側面へ押し込まないでください。

### 非対称レイアウト：コンテンツのオフセットと全画面中央揃えの選び方

（[06:33](https://developer.apple.com/videos/play/tech-talks/111466/?time=393)）コントロールが側面に寄ると、多くの UI は非対称になります。以前は画面全体に対して中央揃えする習慣がありましたが、Duo ではほとんどのコンテンツをオフセットしないと側面コントロールに隠れてしまいます。horizontal safe area insets に揃えると、オフセットは自動で起きます。

オフセットせず画面全体に対して中央揃えできるのは、没入型で視覚性が高く、スクロールしない UI です。ただし右側のコントロールがインタラクティブ要素を隠さないことが前提です。

混在もできます。全幅の背景画像や header に、スクロールする前景を inset する形です。すべてのインタラクティブ要素はスクロール可能な inset 領域内に置き、隠れないようにします。

### 内画面の 3 つのコンテンツ戦略

（[07:37](https://developer.apple.com/videos/play/tech-talks/111466/?time=457)）内画面を「引き伸ばされた iPhone App」にしないでください。講演では次の 3 つの道筋が示されます。

1. **Split view**：複数の情報階層を同時に示す。内外画面のあいだで階層構造は変えない。機能を特定の表示やポーズに限定しない。
2. **ワイド画面向けにコンテンツを再構成**：Music の例。縦に積んだレイアウトが水平スペースの拡大に合わせて 2 列へ再配置される。
3. **Tab bar をサイドバーへ**：情報密度の高い App に向く（Health の例）。すべての App がこうすべきではない。

### Sheet の挙動と折り目回避

（[08:37](https://developer.apple.com/videos/play/tech-talks/111466/?time=517)）Sheet はポーズに応じて変わります。

- **外画面のデフォルト**：sheet のコントロールも側面へ移る。コンテンツが水平バーの方が合う場合は、sheet の vertical bar を無効化できる。toolbar ボタンが 1 つだけの sheet に向く。無効化すると、sheet は前面カメラの少し下で止まり、ステータスバーは再配置される。
- **内画面の縦横**：標準の水平バーを使う。
- **半折り**：sheet はスライドして折り目の上に乗らない。

折り目上のボタンは押しにくいです。システムは sheet、alert、menu、toolbar ボタンなどのコンポーネントに「半折り時にインタラクティブ要素を脇へ押し出す」挙動を内蔵しています。これらのシステムコンポーネントを優先すれば、fold avoidance を無料で得られます。原則は、可能なかぎりインタラクティブ要素を湾曲領域から離すこと。スクロール可能なコンテンツは、その領域を意図的に避ける必要はありません。

### デザイン受け入れチェックリスト（ポーズ視点）

| 確認項目 | 推奨 |
| --- | --- |
| Size Class | outer compact / inner regular だけで判断し、物理解像度に固定しない |
| 側面コントロール | システムマッピングを受け入れる。幅広項目はナビゲーションバーに残す。Live Activities の占有を見込む |
| コンテンツ揃え | 既定ではインタラクティブ内容を horizontal safe area に合わせる。没入背景は全幅でもよい |
| 内外の一貫性 | 開閉後も機能と階層は変えず、能力を特定の pose にロックしない |
| 半折り | システム sheet/alert/menu/toolbar を使い、インタラクティブ要素を自動で折り目から離す |
| 任意のハンズフリーレイアウト | 上にメディア・下にコントロールでもよいが、コントロール集合と階層は他ポーズと揃える |

## 重要ポイント

**1. まず「側面コントロール占有後」のコンテンツ欄を描き、そのあとビジュアル稿を描く**

外画面の稿では右側の縦バー（ステータスバーと Live Activities が展開しうる高さも含む）を確保し、メインコンテンツを従来 iPhone に匹敵する左側領域に置きます。この枠で既存ページを見直し、どの中央揃え要素が隠れるか、どの toolbar 項目が広すぎてナビゲーションバーに残すべきかを確認します。

**2. 内画面には「等比拡大」ではなく「階層の展開」を用意する**

リスト + 詳細、ブラウズ + 再生キュー、概要 + 明細など、regular width で両方を同時に見せられる 2 欄構造を選びます。Music の「縦積み → 2 列」と Health の「tab → sidebar」を対照し、先に情報アーキテクチャを決め、装飾はそのあとです。

**3. 開閉の一貫性ウォークスルーを一度行う**

App 内の主要な操作（作成、編集、共有、設定への入口）をすべて列挙します。outer compact と inner regular を行き来し、各項目に到達できること、階層名や入口位置の意味が一致することを確認します。「展開時だけ現れる」隠れ機能を特に拾います。

**4. 半折りシーンでは、システムコンポーネントが担う主操作だけを置く**

確認ページ、削除確認、オーバーフローメニュー、ツールバーボタンは、できるだけシステム sheet / alert / menu / toolbar を使います。カスタムのフローティングボタンが中央の継ぎ目に落ちると、半折りでは押しにくくなります。システムコンポーネントへ移せるなら移し、移せないなら両側または下半分の届く領域に置きます。

**5. 任意のハンズフリーレイアウト：同じコントロール一覧をコピーする**

机置きの「上メディア・下コントロール」ページを作るなら、他ポーズですでに存在するコントロール一覧を先に書き、ハンズフリー稿で項目ごとにチェックします。欠けた項目があれば足し、デバイスを閉じたあとで先ほど使った操作が見つからない事態を避けます。
